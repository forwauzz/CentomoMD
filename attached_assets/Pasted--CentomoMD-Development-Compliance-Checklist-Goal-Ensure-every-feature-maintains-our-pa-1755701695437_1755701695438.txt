# CentomoMD Development Compliance Checklist

> **🎯 Goal:** Ensure every feature maintains our path to 65% TGV compliance for a ZERO-RETENTION platform  
> **📋 Usage:** Check relevant sections before implementing any feature or making changes  
> **🔄 Status:** Living document - update as compliance requirements evolve  
> **⚡ KEY PRINCIPLE:** CentomoMD stores NO patient data permanently - all data is processed and immediately deleted  

---

## 🚦 **PRE-DEVELOPMENT COMPLIANCE GATE**

**Before starting ANY new feature or change, ask:**

### ✅ **Data Impact Assessment - ZERO RETENTION MODEL**
- [ ] Does this feature process patient/health data? *(Must be immediately processed and deleted)*
- [ ] Does this feature temporarily store data during processing? *(Must have automatic cleanup)*
- [ ] Does this feature involve user authentication or session data? *(Minimal necessary data only)*
- [ ] Does this feature integrate with external services? *(No patient data can leave our system)*
- [ ] Does this feature change data processing workflows? *(Ensure zero retention maintained)*

**ZERO RETENTION PRINCIPLE:** Any patient health data must be processed in-memory and immediately deleted. Only user account data and non-health metadata can persist.

## 🔒 **SECURITY & ACCESS CONTROL CHECKLIST - ZERO RETENTION**

### **For ANY feature that processes user data:**

#### Authentication & Authorization *(Minimal Data Storage)*
- [ ] **User Authentication:** Does the feature require login? *(Store only username/email + hashed password)*
- [ ] **Session Management:** Session data minimized? *(Only essential session info, auto-expire)*
- [ ] **Role-Based Access:** Different user types? *(Store role enum only, not patient data)*
- [ ] **Password Security:** Secure password handling? *(Hash immediately, never store plaintext)*
- [ ] **Session Timeout:** Sessions auto-expire? *(No persistent sensitive data)*

#### Data Protection - ZERO RETENTION
- [ ] **Temporary Processing:** Patient data processed in-memory only? *(No disk writes)*
- [ ] **Immediate Cleanup:** Processing data deleted after use? *(Automated cleanup)*
- [ ] **Input Validation:** All inputs validated before processing? *(Reject invalid data immediately)*
- [ ] **Memory Management:** No sensitive data in logs/dumps? *(Scrub memory after processing)*
- [ ] **API Security:** External APIs don't receive patient data? *(Only metadata/results)*

#### Zero Retention Implementation
```typescript
// Example: Voice processing with zero retention
class ZeroRetentionProcessor {
  async processVoiceToText(audioBuffer: ArrayBuffer, userId: string): Promise<string> {
    let transcribedText: string;
    
    try {
      // Process in memory only
      transcribedText = await this.whisperService.transcribe(audioBuffer);
      
      // Log the processing event (no patient data)
      await this.auditLog({
        userId,
        action: 'voice_processing_completed',
        resourceType: 'session',
        details: { duration: audioBuffer.byteLength }
      });
      
      // Return result immediately
      return transcribedText;
      
    } finally {
      // Explicit cleanup
      audioBuffer = null;
      transcribedText = null;
      // Force garbage collection if needed
      if (global.gc) global.gc();
    }
  }
}
```

## 👥 **PRIVACY & PERSONAL INFORMATION - ZERO RETENTION MODEL**

### **For ANY feature that processes personal data:**

#### Data Processing (Not Storage)
- [ ] **Processing Consent:** User consents to data processing? *(Clear about zero retention)*
- [ ] **Purpose Limitation:** Data processed only for stated purpose? *(AI transcription/processing)*
- [ ] **Processing Minimization:** Processing only necessary data? *(No excess data processing)*
- [ ] **Immediate Deletion:** All health data deleted after processing? *(Automated cleanup)*

#### Zero Retention Privacy Implementation
- [ ] **Transparency:** Users informed about zero retention model? *(Clear privacy notice)*
- [ ] **Processing Notice:** Users know what processing occurs? *(AI enhancement, transcription)*
- [ ] **No Data Export:** No patient data available for export? *(Only user account data)*
- [ ] **Session Cleanup:** Session data cleaned after logout? *(Complete session clearing)*

#### Zero Retention Consent Template
```typescript
interface ZeroRetentionConsent {
  userId: string;
  consentType: 'voice_processing' | 'ai_enhancement' | 'session_data';
  processingPurpose: string;
  dataRetention: 'zero' | 'session_only' | 'account_only';
  consentGiven: boolean;
  consentTimestamp: Date;
}

// Consent verification before processing
async function verifyZeroRetentionConsent(userId: string, processingType: string) {
  const consent = await getConsent(userId, processingType);
  if (!consent || !consent.consentGiven) {
    throw new Error('User consent required for data processing');
  }
  if (consent.dataRetention !== 'zero' && processingType.includes('health')) {
    throw new Error('Zero retention required for health data processing');
  }
}
```

#### What CAN be stored (Non-Health Data):
- [ ] **User Account Info:** Username, email, password hash, preferences
- [ ] **Usage Analytics:** Aggregated, anonymized usage statistics
- [ ] **System Logs:** Technical logs without patient data
- [ ] **Audit Trails:** User actions without health data content

## 📊 **AUDIT & LOGGING - ZERO RETENTION MODEL**

### **For ANY feature that processes data:**

#### Audit Trail Requirements (No Patient Data)
- [ ] **User Actions:** Log WHO performed action? *(User ID, timestamp, no health data)*
- [ ] **Processing Events:** Log WHAT was processed? *(Type of processing, duration, no content)*
- [ ] **System Events:** Log technical events? *(Errors, security events, performance)*
- [ ] **Access Attempts:** Log authentication attempts? *(Success/failure, IP, no session content)*
- [ ] **Data Flow:** Log data processing flow? *(Input → Processing → Output, no actual data)*

#### Zero Retention Audit Implementation
```typescript
// Audit logging that preserves privacy
interface ZeroRetentionAuditLog {
  id: string;
  userId: string;
  timestamp: Date;
  action: string;
  processingType: 'voice_transcription' | 'ai_enhancement' | 'export_request';
  metadata: {
    duration?: number;        // Processing time
    dataSize?: number;       // Size of processed data (bytes)
    success: boolean;        // Processing success
    errorType?: string;      // Error category (no details)
  };
  ipAddress: string;
  userAgent: string;
  // NO PATIENT DATA OR ACTUAL CONTENT LOGGED
}

// Example usage
async function auditProcessingEvent(userId: string, event: {
  action: string;
  processingType: string;
  dataSize: number;
  success: boolean;
}) {
  await db.insert(auditLogs).values({
    userId,
    timestamp: new Date(),
    action: event.action,
    processingType: event.processingType,
    metadata: {
      dataSize: event.dataSize,
      success: event.success,
      duration: Date.now() - event.startTime
    },
    // Never log actual patient data content
  });
}
```

#### Audit Retention Policy
- [ ] **Technical Logs:** Keep for operational needs (30-90 days)
- [ ] **Security Logs:** Keep for security analysis (1 year)
- [ ] **User Action Logs:** Keep for accountability (3-7 years, no health data)
- [ ] **Processing Logs:** Keep minimal metadata only (30 days)

## ⚠️ **RED FLAGS - STOP AND REVIEW**

**Immediately escalate to compliance review if:**

- [ ] Feature attempts to store ANY patient health data permanently
- [ ] Feature creates database tables for health/medical information  
- [ ] Feature integrates with external services that could receive patient data
- [ ] Feature implements data export containing health information
- [ ] Feature changes the zero-retention processing model
- [ ] Feature involves communication that stores message content
- [ ] Feature caches patient data beyond single session
- [ ] Feature logs actual patient data content (not just metadata)
- [ ] Feature implements backup/sync of health data
- [ ] Feature allows bulk processing that might store intermediate results

**ZERO RETENTION VIOLATIONS = IMMEDIATE STOP**
